xewe-os-modules 3.1.1

The module set 3.1.1: all eight XeWe OS modules, each released on its own at 3.1.1 and marked
together by this tag. Projects pin the set: xewe.toml [modules] ref = "3.1.1".

What is new

- The module Config.h files are in the final form of XeWeCore's doc/config.md: every text line a
  /* */ block comment, two sections between start and end marker lines ("default runtime values",
  "compile time defined constants"), a value the first boot asks for marked "asked at first boot"
  and defining its <NAME>_PROMPT. The first-boot section of 3.1.0 is gone. No define is renamed and
  no value changes; led, led-web, wifi, time and web-interface are the modules with a Config.h.
- The validator rule config checks the paired markers, the block-comment form and the _PROMPT
  placement; doc/contract.md section 3.2 describes the form.
- A project generated by xewe-os-tools 3.1.5 gets each module's values as a framed block of
  commented-out lines; uncomment a line to override its default. A project generated by an older
  tools release keeps its old blocks: delete them and run xewe modules generate again.
- buttons, pins and scheduler: no code change.

Modules

- buttons, led, led-web, pins, scheduler, time, web-interface, wifi: each 3.1.1, one release
  per module.

Requirements

- XeWeCore >=3.1.0,<4.0.0; xewe-os-tools 3.1.5 or later for the final Config.h form.

Testing

release_card.md, generated by scripts/release.sh --prepare 3.1.1 --all and attached to this release.
