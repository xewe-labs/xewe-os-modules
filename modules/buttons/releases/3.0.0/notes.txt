buttons 3.0.0

Binds CLI commands to physical buttons. Each mapping ties a GPIO, an input mode (pullup or
pulldown), an event (on_press, on_release, on_change) and a debounce time to one command, so a
button can run anything the console can. Mappings are stored in NVS and restored at boot.

3.0.0 follows 0.3.0 (untagged; v0.2.0 shipped it as 0.2.0). It is part of the xewe-os-modules
3.0.0 set; projects get it through the set tag: xewe.toml [modules] ref = "3.0.0".

CHANGED SINCE 0.2.0

- Pin registry: add claims the GPIO for buttons and refuses a pin another module holds; a
  stored mapping whose pin is taken is reported at boot and ignored; remove releases the
  pin once no mapping uses it.
- New $buttons schema: every mapping as a JSON Lines row ("group":"button"), also in
  $system schema.
- add and remove report failure (an unknown id, a refused pin) instead of passing silently.
- Replies follow one style: "Buttons: button mapping added" / "... removed", errors
  "! Buttons: ..." (was "Successfully added button mapping." and "Error: ...").
- Arguments are parsed with the core parsers; no iostreams, no exceptions.
- Same NVS key as 0.2.0 (buttons/data, one FlexData blob).
- The source is formatted with the tools' clang-format style (layout only).
- Commits: df801b4, 3032fc2, ac2bdaa, 78f0088, 4c4fe65, 423987b, then the 3.0.0 work, format and
  prepare commits.

REQUIREMENTS

- XeWeCore >=3.0.0,<4.0.0 (requires_core). ESP32-C3, C6 or S3 with arduino-esp32 3.x; built with
  esp32 core 3.3.12.
- Modules: none. Libraries: none outside the esp32 core.

SETTINGS AND COMMANDS

- $buttons add <pin> "<cmd>" <pullup|pulldown> <on_press|on_release|on_change> <debounce_ms>
- $buttons remove <id>, $buttons status (table of mappings), $buttons schema.
- No settings table. NVS: buttons/data (every mapping).

KNOWN BEHAVIOUR

- Several mappings may share a pin; another module's pin is refused.
