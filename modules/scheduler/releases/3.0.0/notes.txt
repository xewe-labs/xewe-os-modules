scheduler 3.0.0

Runs stored commands on a weekly schedule. A block has a start and end minute (0-1439), a
day (0 = Monday ... 6 = Sunday), a colour for interfaces that draw it, and one or more commands
separated by |; the start minute runs them. Blocks are stored in NVS.

3.0.0 follows 0.3.0 (untagged; v0.2.0 shipped it as 0.2.0). It is part of the xewe-os-modules
3.0.0 set; projects get it through the set tag: xewe.toml [modules] ref = "3.0.0".

CHANGED SINCE 0.2.0

- New $schedule schema: every block as a JSON Lines row ("group":"schedule", with the
  $schedule add command as its "set" hint), also in $system schema.
- The help sample of $schedule add is copy-pasteable.
- Replies follow one style: "Scheduler: schedule saved" / "... removed", errors
  "! Scheduler: ...". Arguments are parsed with the core parsers.
- Same NVS key as 0.2.0 (schedule/schedules, one FlexData blob).
- The source is formatted with the tools' clang-format style (layout only).
- Commits: df801b4, 3032fc2, ac2bdaa, 78f0088, c337b20, 4c4fe65, 423987b, then the 3.0.0 work,
  format and prepare commits.

REQUIREMENTS

- XeWeCore >=3.0.0,<4.0.0 (requires_core). ESP32-C3, C6 or S3 with arduino-esp32 3.x; built with
  esp32 core 3.3.12.
- Modules: time (and, through it, wifi). Libraries: none outside the esp32 core.

SETTINGS AND COMMANDS

- $schedule add <start> <end> <day> <RRGGBB> "<cmd1|cmd2>", $schedule remove <id>,
-   $schedule status (all blocks as JSON), $schedule schema. Id: schedule.
- No settings table. NVS: schedule/schedules (every block).

KNOWN BEHAVIOUR

- Nothing runs until time has synced the clock. Blocks are checked once a minute; only the
  start minute triggers. The schedule is active after the reboot that follows first setup.
- It needs time, which needs wifi: while Wi-Fi is down the device waits in the wifi module
  (by design, see the wifi notes).
