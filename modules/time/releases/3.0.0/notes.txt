time 3.0.0

NTP time sync and timezone handling. On first boot it detects the offset from three geo-IP
services in parallel (the first valid answer wins) and asks for confirmation, or for a
GMT+HH:MM value; later boots apply the stored offset and wait for SNTP. Other modules read
the time through it.

3.0.0 follows 0.3.0 (untagged; v0.2.0 shipped it as 0.2.0). It is part of the xewe-os-modules
3.0.0 set; projects get it through the set tag: xewe.toml [modules] ref = "3.0.0".

CHANGED SINCE 0.2.0

- Settings table: tz_gmt_str (str <= 9, default GMT+00:00) with $time set|get|schema;
  GMT-8 is normalised to GMT-08:00 and applied at once, an unparsable value is put back.
  $time set_zone stays as its alias.
- Replies follow one style: "Time: timezone set to ...", errors "! Time: ..."; the core's
  GMT offset parser replaces the hand-written one.
- Same NVS key as 0.2.0 (time/tz_gmt_str).
- The source is formatted with the tools' clang-format style (layout only).
- Commits: df801b4, 3032fc2, ac2bdaa, 78f0088, 4c4fe65, 423987b, then the 3.0.0 work, format and
  prepare commits.

REQUIREMENTS

- XeWeCore >=3.0.0,<4.0.0 (requires_core). ESP32-C3, C6 or S3 with arduino-esp32 3.x; built with
  esp32 core 3.3.12.
- Modules: wifi. Libraries: none outside the esp32 core (HTTPClient, SNTP).

SETTINGS AND COMMANDS

- $time set_zone GMT+HH:MM, $time fetch, $time set|get|schema (tz_gmt_str).
- Setting: tz_gmt_str. NVS: time/tz_gmt_str.
- API: get_current_time(), get_current_time_str(), print_current_time().

KNOWN BEHAVIOUR

- First boot waits up to 6 s for a geo-IP answer, then asks; a boot waits for SNTP up to
  10 s (50 x 200 ms).
- It needs wifi: while Wi-Fi is down the device waits in the wifi module (by design, see the
  wifi notes).
