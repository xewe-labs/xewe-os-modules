web-interface 3.0.0

An HTTP page and a command endpoint for other devices on the network: GET /console serves
a small command page, GET /cmd?c=<command> runs a console command. A project can take over
GET / with its own page.

3.0.0 follows 0.3.0 (untagged; v0.2.0 shipped it as 0.2.0). It is part of the xewe-os-modules
3.0.0 set; projects get it through the set tag: xewe.toml [modules] ref = "3.0.0".

CHANGED SINCE 0.2.0

- Settings table: port (u16, default 80, applies after a restart) and root (str <= 31: GET /
  redirects there; empty = the command page), with $web_interface set|get|schema.
- Root hook: set_root(handler) (RAM only, from setup()) lets a project page own /, ahead of
  the root setting; redirect_root(path) is the stored form. The command page is now always
  at /console.
- $web_interface status adds the port and root lines to uptime and memory usage.
- The source is formatted with the tools' clang-format style (layout only).
- Commits: df801b4, 3032fc2, ac2bdaa, 78f0088, 4c4fe65, 423987b, then the 3.0.0 work, format and
  prepare commits.

REQUIREMENTS

- XeWeCore >=3.0.0,<4.0.0 (requires_core). ESP32-C3, C6 or S3 with arduino-esp32 3.x; built with
  esp32 core 3.3.12.
- Modules: wifi. Libraries: none outside the esp32 core (WebServer).

SETTINGS AND COMMANDS

- $web_interface status, $web_interface set|get|schema (port, root). Id: web_interface.
- HTTP: GET /, GET /console, GET /cmd?c=<command> (200 OK, or 400 Empty Command).
- Settings: port, root. NVS: web_interface/port, web_interface/root.

KNOWN BEHAVIOUR

- No authentication: anyone on the same network can run any command. Trusted networks only.
- It needs wifi: while Wi-Fi is down the device waits in the wifi module (by design, see the
  wifi notes).
